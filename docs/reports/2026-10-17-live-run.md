## Findings

1. **Fixed during the run (`c8fdd2e`).** Rule 6 refused the main checkout as "config unreadable"
   once `disable` had enabled `extensions.worktreeConfig` for a linked worktree (the main checkout
   has no `config.worktree`), and refused Orca's own `push.autoSetupRemote`. A missing file is now
   an empty scope; `push.autosetupremote` is allowlisted. Tests added.
2. **Screenshots are never saved.** `chrome-devtools-mcp` refuses to write outside its workspace
   roots, and `R/screenshots` is outside `WT`. The UI reviewer passed without screenshots.
   Fix: point the MCP's allowed roots at `R/screenshots`, or screenshot into a `WT`-local
   excluded dir and copy out.
3. **A conflict hold cannot be cleared by rework.** The squash merge always uses the job's
   original `base` as merge base and the builder may not rebase or merge, so a rework of 003
   collides on the same lines in any later run. Needs a design change (e.g. a rework of a
   conflict hold restarts the branch from the current run base with the previous diff as input).
4. **Report noise.** A clean overlap check (`paths: []`) still prints an empty
   "Overlaps with origin/main:" line under *Needs your attention*.
5. **Coordinator ergonomics (my errors, worth hardening in SKILL.md).** The skill's dev-server
   recipe leaves the coordinator to find the process-group id; `pgrep -f` matched the
   coordinator's own shell and the wrong group was recorded (the server was stopped by hand).
   Recording `$!` of the `setsid` launch would avoid it. Separately, one builder was started
   with an empty task text (a coordinator scripting mistake) and was recovered with
   `orchestration send` plus a reply to its question.
6. **Orca names the worktree branch `factory-<id>`;** the skill's `switch -C factory/<id>` fixes it,
   leaving an unused `factory-<id>` branch that the coordinator deletes. Harmless, but a
   `--branch` option at create time (if Orca offers one) would be cleaner.
